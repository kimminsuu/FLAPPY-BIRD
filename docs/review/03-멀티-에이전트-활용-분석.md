# 03. 멀티 에이전트 활용 분석

> 프로젝트에서 설정한 AI Agent 전략이 실제로 효과적이었는지 분석합니다.

---

## 1. 설정된 Agent 전략

### CLAUDE.md에 정의된 3가지 Agent

| Agent | 역할 | 실행 시점 |
|-------|------|-----------|
| code-review | 코드 품질 체크 | 커밋 직전 |
| security-guidance | 보안 취약점 점검 | 커밋 직전 (보안 관련 파일 변경 시) |
| pr-review-toolkit | PR 메타데이터 검증 | PR 생성 직후 |

### 2-포인트 실행 전략
```
커밋 직전 → code-review + security-guidance (1회)
PR 생성 직후 → pr-review-toolkit (1회)
```

---

## 2. 실제 활용도 평가

### code-review Agent
- **활용 빈도**: 중간
- **효과**: 주로 타입 안전성, 미사용 변수, 잠재적 null 참조 등을 잡아냄
- **한계**: 게임 로직(물리엔진, Canvas 렌더링)은 "실행 제외 대상"으로 분류했으나, 실제로는 게임 로직에서도 코드 품질 이슈가 있었음 (예: 1,900줄 단일 파일)
- **평가**: ★★★☆☆ — 유용하지만, 구조적 문제(파일 크기, 관심사 미분리)는 감지 못함

### security-guidance Agent
- **활용 빈도**: 낮음
- **효과**: `security-review.md`에 6개 보안 점검 항목을 도출
  - 하드코딩된 마스터 계정 상수
  - localStorage 데이터 서버 검증 미비
  - 페이지별 인증 가드 부재
- **한계**: 실행 조건("보안 관련 파일 변경 시")이 너무 좁아서 실행 빈도가 낮았음
- **평가**: ★★★★☆ — 실행 시에는 실질적인 보안 이슈를 발견했으나, 실행 빈도가 부족

### pr-review-toolkit Agent
- **활용 빈도**: PR 생성 시마다
- **효과**: PR 제목/본문 형식, 이슈 연결, 변경 파일 범위 확인
- **평가**: ★★★☆☆ — 형식 검증은 유용하지만, 깊은 코드 리뷰는 code-review와 중복

## 3. 실제로 가장 유용했던 Agent 패턴

### (1) Explore Agent (비공식, 가장 많이 사용)
- CLAUDE.md에는 정의되지 않았으나, 실제 개발에서 가장 자주 사용
- **용도**: 코드베이스 탐색, 기존 패턴 파악, 수정 대상 파일 식별
- **예시**:
  - "사운드 추가할 버튼이 있는 파일을 모두 찾아줘"
  - "daily_work 로그 전체 읽어서 프로젝트 히스토리 파악"
  - "game-page.tsx에서 아이템 충돌 처리 로직 위치 찾기"
- **평가**: ★★★★★ — 대규모 코드베이스 탐색에 필수

### (2) Plan Agent (설계 시 활용)
- 큰 기능 구현 전 계획 수립에 사용
- **예시**: 사운드 시스템 구현 계획, 프레임 드롭 최적화 계획
- **평가**: ★★★★☆ — 복잡한 작업의 방향을 잡는 데 효과적

### (3) code-simplifier Agent (코드 정리)
- 코드 작성 후 자동으로 실행되어 정리/단순화
- **평가**: ★★★☆☆ — 소규모 변경에는 과도, 대규모 리팩토링에는 유용

## 4. 토큰 효율 분석

### 2-포인트 전략의 토큰 절약 효과

| 시나리오 | Agent 실행 횟수 | 예상 토큰 소모 |
|---------|---------------|--------------|
| 매 커밋마다 3개 Agent 실행 (63커밋) | 189회 | ~570K 토큰 |
| 2-포인트 (커밋+PR 시만) | ~30회 | ~90K 토큰 |
| **절약률** | **84% 감소** | **~480K 토큰 절약** |

### 실제 비용 영향
- Opus 기준 입력 $15/M + 출력 $75/M 토큰
- 480K 토큰 절약 ≈ **$7~36 절약** (입출력 비율에 따라)

## 5. 개선 제안

### (1) Agent 실행 조건 세분화
```
현재: "보안 관련 파일 변경 시"
개선: 파일 경로 패턴 매칭
  - lib/supabase.ts, lib/user-service.ts → security-guidance 필수
  - .env*, api/ → security-guidance 필수
  - 나머지 → 선택
```

### (2) Explore Agent 공식화
- CLAUDE.md에 명시적으로 추가
- 사용 가이드라인: "3개 이상 파일 탐색 필요 시 사용"

### (3) 구조 리뷰 Agent 추가 검토
- code-review는 함수 수준 품질만 체크
- **architecture-review**: 파일 크기, 의존성 깊이, 순환 참조 등 구조적 품질 체크
- 실행 시점: PR 생성 시 (code-review와 함께)

### (4) Agent 파이프라인 자동화
```
현재 (수동):
  사용자 → "코드 리뷰 해줘" → Agent 실행

이상적 (자동):
  git commit hook → code-review 자동 트리거
  gh pr create hook → pr-review-toolkit 자동 트리거
```

## 6. 다음 프로젝트를 위한 Agent 전략

### 추천 Agent 구성

| Agent | 실행 시점 | 조건 |
|-------|-----------|------|
| code-review | 커밋 직전 | 항상 |
| security-guidance | 커밋 직전 | `*.env`, `lib/auth*`, `api/` 변경 시 |
| pr-review-toolkit | PR 생성 직후 | 항상 |
| Explore | 작업 시작 시 | 3개+ 파일 탐색 필요 시 |
| Plan | 기능 구현 전 | 3개+ 파일 수정 예상 시 |

### 핵심 원칙
1. **Agent는 도구, 만능이 아님**: 구조적 문제는 사람이 사전에 설계해야 함
2. **토큰 효율 우선**: 매 커밋 실행 대신 의미 있는 시점에만 실행
3. **피드백 루프**: Agent 결과를 무시하지 말고, 반복되는 이슈는 컨벤션으로 승격
