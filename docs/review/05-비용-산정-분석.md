| **합계** | | **$0/월** | |

### 유저 수별 비용 예측

| 유저 수 | 월 비용 | 병목 지점 |
|---------|---------|----------|
| ~1,000명 | $0 | 무료 티어 충분 |
| ~5,000명 | $0~25 | Supabase 대역폭 초과 가능 |
| ~10,000명 | ~$25 | Supabase Pro 필요 |
| ~50,000명 | ~$45+ | Supabase Pro + Vercel Pro |
| 100,000명+ | ~$100+ | 전용 DB 인스턴스 검토 |

### 무료 티어 한계점

#### Supabase Free 주의사항
- **7일 비활성 시 자동 일시정지**: 소규모 앱에서 치명적
  - 해결: Cron job으로 주기적 ping 또는 Pro 업그레이드($25/월)
- **500MB DB 제한**: game_score 테이블이 append-only → 빠르게 증가
  - 1,000유저 × 일 10게임 × 30일 = 300,000행/월
  - 행당 ~100바이트 → ~30MB/월 → 약 16개월 후 한계
  - 해결: 월별 아카이브 또는 집계 테이블 분리
- **200 동시 연결**: 게임 특성상 동시접속이 분산되므로 큰 문제 아님

#### Vercel Hobby 주의사항
- **상업적 사용 불가** (약관상): 인앱 결제 도입 시 Pro($20/월) 필요
- **100GB 대역폭**: 정적 에셋(이미지) 캐싱 필수

## 4. 비용 최적화 팁

### 즉시 적용 가능
1. **이미지 최적화**: 새 이미지 37종을 WebP로 변환 → 대역폭 50%+ 절감
2. **정적 에셋 캐시**: Vercel의 CDN 캐싱 활용 (무료)
3. **game_score 정리**: 월별 집계 후 원본 삭제 → DB 용량 관리

### 중기 검토
4. **Supabase Edge Functions**: 서버 로직이 필요할 때 Vercel API Routes 대신 사용 → Vercel Pro 불필요
5. **오프라인 모드**: 게임 플레이는 로컬, 결과만 동기화 → API 호출 90% 감소

## 5. 비용 산정의 합리성 평가

### 잘한 점
- **무료 티어 최대 활용**: $0/월로 MVP 운영 가능한 스택 선택
- **단계적 스케일링**: 유저 수에 따라 점진적 업그레이드 가능
- **외주 비용 대비 극적 절감**: AI 보조 개발로 700~1,200만원 → 4~8만원

### 보완 필요
- **Supabase 7일 정지 리스크**: 무료 티어의 가장 큰 함정, 사전 대비 필요
- **Vercel 상업적 사용 제한**: 수익화 시 Pro 업그레이드 필수
- **game_score 테이블 증가**: 현재 미사용이지만, 활성화 시 DB 용량 관리 계획 필요
- **앱 스토어 수수료**: 매출의 15~30%는 비용 계획에 반드시 포함

### 종합 평가
> 1인 개발 모바일 게임으로서 **비용 효율성은 매우 우수** (9/10).
> 무료 인프라 + AI 보조 개발로 최소 비용으로 완성도 높은 제품 구현.
> 유일한 고정 비용인 Apple Developer $99/년이 가장 큰 지출 항목이라는 점이 이를 증명.
